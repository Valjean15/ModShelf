# The command line

`ModShelf.Cli` does everything the desktop app does, without a window. It builds the same services as the desktop app
and uses the same library, settings and accounts, so a library made with one shows in the other.

- **Installed app:** it sits beside the desktop app: `%LOCALAPPDATA%\ModShelf.App\current\ModShelf.Cli.exe` on Windows
  and `ModShelf.app/Contents/MacOS/ModShelf.Cli` on macOS. The Linux AppImage holds it too, but starts only the desktop
  app; use a build from source there.
- **From source:** `dotnet run --project src/ModShelf.Cli -- <command>`.

```text
ModShelf.Cli download <link> [--to <folder> [--name <file>]] [--with-requirements [--deep] [--yes]]
ModShelf.Cli mod show <link> [--all] [--changelog]
ModShelf.Cli mod games [words] [--source <site>] [--page <n>] [--page-size <count>] [--installed]
ModShelf.Cli mod search [words] --game <game> [--author <name>] [--category <name>] [--updated-within <days>] [--adult] [--sort <order>] [--ascending] [--page <n>] [--page-size <count>]
ModShelf.Cli mod updates --game <game> [--since 1d|7d|28d|<date>]
ModShelf.Cli mod tracked [--source <site>]
ModShelf.Cli mod track <link>
ModShelf.Cli mod untrack <link>
ModShelf.Cli mod endorse <link>
ModShelf.Cli mod abstain <link>
ModShelf.Cli library list [--files]
ModShelf.Cli library watch <link>
ModShelf.Cli library unwatch <link>
ModShelf.Cli library pin <link>
ModShelf.Cli library unpin <link>
ModShelf.Cli library skip <update link> [--undo]
ModShelf.Cli library note <link> [text] [--clear]
ModShelf.Cli library forget <link>
ModShelf.Cli library rescan [link]
ModShelf.Cli library check
ModShelf.Cli library updates [--changelog]
ModShelf.Cli library move <folder>
ModShelf.Cli library move-game <game> [folder] [--yes]
ModShelf.Cli library export [--to <file>] [--game <game>]
ModShelf.Cli library import <file-or-link> [--watch-only] [--optional] [--newest-for-missing] [--yes]
ModShelf.Cli library import-archives <folder> --game <site/game> [--yes]
ModShelf.Cli library cleanup [--game <site/game>] [--delete <group> [--yes]]
ModShelf.Cli settings show
ModShelf.Cli settings set <setting> <value>
ModShelf.Cli settings reset <setting>
ModShelf.Cli links status|take|give-back [site]
ModShelf.Cli diagnostics
ModShelf.Cli queue list
ModShelf.Cli account list
ModShelf.Cli account link <source> [--with api-key|browser|email|profile]
ModShelf.Cli account check <source>
ModShelf.Cli account unlink <source>
ModShelf.Cli mcp
```

Every setting named here in `code` is described in [settings.md](settings.md), and where ModShelf keeps the library
database, credentials and logs is in [settings.md › Where ModShelf keeps its data](settings.md#where-modshelf-keeps-its-data).

## Downloading

- `download` queues the file and shows its progress until it's done. Put the link in quotes, since shells treat characters such as `&` specially. A file that won't fit on the disk fails before anything is written. One process at a time runs the downloads of a library: while the desktop app or another `download` runs them, `download` says so and exits 1, leaving the queue alone.
- **Into the library:** without `--to`, the file goes under the library root, or its game's own folder when it has one (`games.<site>/<game>.root`), in its mod's folder, and the library records it, with its mod watched for updates. The file keeps the name its site gives it, made safe on every system; when another file has that name, the file's ID is added to it. A file the library has, still on disk, isn't downloaded again. Only files of mods on sites such as Nexus Mods go into the library.
- **Old versions:** the files a download replaced, as its site says (Nexus Mods' update chains), are its old versions; on GameBanana, an archived file is an old version of the newer file of the same name, its version left out; on mod.io, each file is an old version of the next one uploaded, up to the live one; DEG Mods lists no file its author replaced, so none is an old version, and the one downloaded before stays as it is; on Thunderstore, each version is an old version of the next one uploaded. By default, the two newest versions stay and older ones are **deleted for good**, once the library has recorded the new file; `library.oldVersions` can keep them all, or move them to an `_archive` folder instead. `download` says what it moved or deleted.
- **Into a folder of your own:** `--to` saves any file there, such as one from a plain web link, and `--name` picks its name. The folder is created if it doesn't exist; a file there instead is refused. A file saved there already by an earlier `download` isn't downloaded again. To check the file against a hash, end the link with `#sha256=<hex>` (or `md5`, `sha1`, `sha512`); the fragment is never sent to the server.
- **With what it needs:** `--with-requirements` first lists what the file's mod needs, as its site lists it (Nexus Mods' requirements, mod.io's dependencies): each mod with what becomes of it, its newest main file to download, already in the library, already downloading, or why it can't be downloaded, and things off the site, such as a script extender, with their pages, which ModShelf never downloads. `--deep` also lists what those mods need, down to three levels, each mod once, under what needs it. Only with `--yes` do the mods the library lacks download into it too, after the file, each followed as the file is; one that can't be queued is named with why, and the exit code is 1. It goes into the library only, so `--to` is refused, and a site that doesn't list what mods need downloads the file alone. The site's list can be wrong or out of date; nothing is installed.
- **Speed:** `settings set downloads.speedLimit 2MB` limits the queue's downloads to 2 MB a second together, `off` turns the limit off, keeping the speed, and `on` turns it on again. A running `download` takes the change within seconds, from another command line or the desktop app.
- Ctrl+C stops the download and keeps what's downloaded so far. Running the same command again continues where it stopped, including after a crash.
- When a site wants a download started on its website, `download` opens the page in your browser, shows it, and asks for the link the site then hands over. Paste it and press Enter, and the download carries on. Ctrl+C leaves the download waiting; running the same command again shows the page again.
- **Nexus Mods downloads:** `download` takes a mod's page (its newest main file), a file's link from the mod's Files tab, or an `nxm://` link, and needs a linked account. Premium accounts download straight away. Free accounts start each download on the website with "Slow download"; the website then hands your browser an `nxm://` link to paste. While the desktop app opens these links (`links take`), it gets the link instead and carries the download on there. Otherwise the app that opens them gets it, such as Vortex or Mod Organizer 2; with none, the browser usually shows the link it couldn't open: Chrome and Edge in the developer tools' console, Firefox in its address bar. `download "nxm://…"` on its own also finishes a download waiting for it: in the library, or with `--to`, in that folder. A file the browser downloads with "Manual download" instead is taken from its downloads folder, or from the path typed at the prompt.
- **GameBanana downloads:** `download` takes a mod's page or its download page (the archive it got last), or a file's 1-click link, which names its mod, as `mod show` lists it (`https://gamebanana.com/mmdl/<file>,Mod,<mod>`) or as GameBanana's **1-Click Install** button hands it to a mod manager, behind its scheme. It needs no account. A 1-click link without its mod is refused: GameBanana doesn't say whose file it is.
- **mod.io downloads:** `download` takes a mod's page (`https://mod.io/g/<game>/m/<mod>`, its live file for Windows), or a file's link as `mod show` lists it, on mod.io's API (`https://g-<game>.modapi.io/v1/games/<game>/mods/<mod>/files/<file>/download`). It needs a linked API key or access token; the few games that give their files to an access token only refuse a key. A file mod.io's virus scan found malicious is refused; one it says may be harmful, such as one with a program in it, is downloaded, and the log says so. The MD5 is checked.
- **DEG Mods downloads:** `download` takes a mod's page (`https://degmods.com/mod/<naddr>`, its first file), its address (`nostr:naddr1…`), or a file's link as `mod show` lists it (the mod's page with `#file=<id>`). It needs no account. DEG Mods' mods are Nostr events on its relays, each one's signature checked; a relay that doesn't answer within 30 seconds isn't asked for the next 5 minutes, so the others' answers don't wait for it, and the log says so once. Its games' covers in the desktop app come from the games database its admin publishes, CSV files read once a run, about 28 MB, the first time its games are listed (a game it lacks shows its initial; the command line reads none); its files are on Blossom servers, which name a file by its SHA-256, and ModShelf takes one from a server other than DEG Mods' own, which gives files only to its site after showing an ad. A file elsewhere whose link gives the file itself, such as one on RPGHQ's file host, ModShelf downloads too, having asked the link what it gives. A file only DEG Mods' server has, and a file on MediaFire, Google Drive, Mega or another page, opens in the browser, and the download waits for the file: ModShelf takes it from the browser's downloads folder (`downloads.browserFolder`) when the browser saves it there, or from the path you type at the prompt, checking the SHA-256 when the author gave it, and moves it into the library. A link to your own computer or network is never asked. The SHA-256 is checked when the author gave it. Mods DEG Mods' moderation hides or blocks, and mods sexualizing minors whatever it says, are left out, and their links refused.
- **Thunderstore downloads:** `download` takes a package's page in a community (`https://thunderstore.io/c/<community>/p/<team>/<name>/`, its newest version), a version's page (`…/v/<version>/`), its download link (`https://thunderstore.io/package/download/<team>/<name>/<version>/`), or the `ror2mm://` link the website's **Install with Mod Manager** opens. It needs no account. The last two name no community, so Thunderstore is asked which lists the package; a package listed in several, such as BepInEx's pack, needs its page's link, which names the game. Each version is a file, `Team-Name-1.2.3.zip`, the newest the main one. A community's packages are read from its whole listing the first time it's needed in a run: seconds for most, but tens of seconds and about 38 MB for Lethal Company. Thunderstore gives no hashes. Nothing is installed or extracted.

## Looking mods up, searching and following them

- `mod show` looks a mod up from a link to it or to one of its files, and prints its details and its files by section, newest first, each with the link to download it. The file the link points to is marked. `--all` adds old versions, archived files and files in no section; `--changelog` adds the changelog. Nothing is downloaded.
- `mod games` lists a site's games whose names match the words, those that start with them first, each with the key `mod search --game` takes, 20 a page unless `--page-size` says (1 to 100); `--page` picks the page, and `--source` the site, when more than one has games. GameBanana has too many games to list them all, so its games need words, one of them 3 letters or more, which GameBanana's own search finds them by. mod.io lists the games open to apps such as ModShelf, about 400; DEG Mods the games its mods are of, about 250; Thunderstore its communities, about 380. With `--installed`, it lists the games Steam installed on this computer instead, as Settings › Games does: a row for each game on each site, its key, and how it matched ("same name", "one of the same name", "chosen" or "none, chosen"), the words keeping the games whose names, or their games' names, have them, and `--source` keeping that site's games alone; a site that can't list its games is said, and its games then match only as chosen in the desktop app.
- `mod search` lists a game's mods whose names hold the words, a page at a time, with author, approval in the site's words (endorsements on Nexus Mods, likes on GameBanana and Thunderstore, positive ratings on mod.io; no column for a site without, such as DEG Mods), downloads, last update and the link `mod show` and `download` take. The game is named as its site names it: as in its links on Nexus Mods, such as `stardewvalley`, by its number on GameBanana and mod.io, such as `16951` or `6715`, by its name in lowercase on DEG Mods, such as `"fallout: new vegas"`, and by its community on Thunderstore, such as `lethal-company`; `mod games` gives each game's. Thunderstore leaves out deprecated packages, as its website does. On DEG Mods, `--author` takes an author's `npub1…`, as its results name them. `--author` keeps one author's mods, `--category` one of the game's categories, by its name in any case (one the game doesn't have is refused, naming those it has), `--updated-within` the mods updated within that many days, counted from the start of the hour, and `--adult` includes mods with adult content. `--sort` orders by `Relevance`, `Endorsements` (whatever the site counts as approval), `Downloads`, `UniqueDownloads`, `Updated`, `Newest`, `Size` or `Name`, the most first, and by name from Z; the site's own order unless set (relevance on Nexus Mods, which without words is its own order; best match on GameBanana, which without words is the newest). `--ascending` puts the least first, such as the oldest, or names from A. `--page` picks the page, and `--page-size` how many mods it lists, from 1 to 100 and as many as the site's pages hold (20 unless set, or fewer when the site's pages hold fewer). A search the site can't do, such as by author on a site that can't, is refused, saying what it can. A site that marks mods with adult content but can't leave them out, such as GameBanana, has them left out after it answers, unless `--adult` is given: the page lists fewer, and says how many it left out.
- `mod updates` lists a game's mods that changed since a time, in one request: each with when its files last changed, when it was last active, and its link. Mods with new or changed files since then are marked; the others only changed their pages, such as their descriptions or comments. `--since` takes `1d` (the default), `7d` or `28d`, or a date or time such as `2026-10-20` or `2026-10-20T18:00`, in local time unless it gives an offset. Nexus Mods lists the last 28 days only. mod.io lists the mods whose live file changed, in the last 28 days too; with more than 1,000 changes since then, `library check` asks each mod instead. DEG Mods lists the mods changed in any way in the last 28 days, each to be checked. Thunderstore lists the packages updated in the last year, from its listing.
- `mod tracked` lists the mods your linked account follows on the site. `mod track` and `mod untrack` follow the mod a link is to, or stop following it, as the site's button does; doing either twice changes nothing. They say it in the site's words, such as "Tracked on Nexus Mods: mod 12604 of skyrimspecialedition." and "12 tracked mods on Nexus Mods." On GameBanana, `mod tracked --source gamebanana` lists the mods your linked profile subscribes to; ModShelf can only read them, so `mod track` and `mod untrack` refuse its mods and say to change them on GameBanana's website. On mod.io, `mod tracked --source modio` lists the mods your access token subscribes to, read only too; an API key lists none.
- `mod endorse` endorses the mod a link is to with your linked account, as the site's own button does, and `mod abstain` chooses not to, or takes an endorsement back. They say it in the site's words, such as "Endorsed on Nexus Mods: mod 12604 of skyrimspecialedition." Nexus Mods is the only site ModShelf can endorse on; it refuses some mods, such as one your account hasn't downloaded, and the command says why in its words, with exit code 1. A link to another site's mod is refused, with exit code 2.
- When more than one site can search, list updates or follow mods, `--source` picks one, such as `--source nexus`, `--source gamebanana`, `--source modio`, `--source degmods` or `--source thunderstore`. Without it, a game named by its key alone is the site's whose games' keys look like it: a name of lowercase letters, digits and hyphens is Nexus Mods', a lowercase name with a space or other punctuation DEG Mods', and a number GameBanana's or mod.io's, so it needs `--source`; Thunderstore's games always need theirs, `--source thunderstore`, since their keys look like Nexus Mods'. Where a game is named with its site, as `library export --game` and the `games.<site>/<game>` settings name it, `thunderstore/lethal-company` names Thunderstore's Lethal Company, and `degmods/starfield` DEG Mods' Starfield. Messages name a site by its name, such as "mod 12604 of skyrimspecialedition on Nexus Mods", and by its ID where you type it, such as `account link nexus`.

## The library

- `library list` shows the library: the mods ModShelf watches for updates, and the ones with downloaded files, each with its link; `--files` also lists each file with its version, size, SHA-256 and path. The SHA-256 is read once, when a download is recorded; a file recorded before 0.9.2 has none until a rescan reads it. `library watch` adds the mod a link is to and watches it; `library unwatch` stops watching it, and a mod without downloaded files leaves the library. `library forget` takes a mod out of the library, with its updates, so it isn't watched any more: its downloaded files stay on disk, no longer the library's, so moving the library leaves them behind, and its completed downloads leave the downloads list, which would add them back. It waits until the mod's downloads into the library are finished. Watching is ModShelf's own, apart from a site's tracked mods.
- `library pin` pins a library mod at the version it has: its updates are still found, but aren't offered, so `library updates`, `library check`, the desktop app and its notices leave them out; `library unpin` offers them again. `library skip` skips one update, by the link `library updates` gives it, until a newer one comes, and `--undo` offers it again. `library note` keeps a note of a mod, up to 2,000 characters, in place of the one it had, and `--clear` removes it. None of them asks the site, and `library list` says which mods are pinned, and lists the notes and the mods gone from their sites, each with when a check first found it gone.
- `library rescan` looks in the mods' folders, where their files are and where the folder pattern puts new ones, each with its `_archive` folder, for files the library doesn't know, such as ones downloaded outside ModShelf. It adds each that matches one of the mod's files on its site by name, as ModShelf saves it or with the file's ID added, and by size, within 1 KB, and reads the SHA-256 of the library's files that have none. It says which files are missing from disk, and which in the folders match nothing. With a link, it rescans that mod, which comes into the library, watched, when its files are found where the folder pattern puts them, as a forgotten mod's do. Nothing is moved, renamed or deleted, and the site is asked only about mods with files to match.
- `library check` checks the watched mods for updates now, and lists the new ones with the link to download each. An update is the newest file of a downloaded file's update chain on the site, or, for a main file the author didn't link, a newer main file; for a mod that's only watched, a main file uploaded since the last check. A mod with files also gets the optional files uploaded since the last check that it doesn't have, marked as new optional files; once one is downloaded, its own updates follow. Version labels are never compared. A mod whose site won't list its files, and then says it's hidden or removed, or no longer knows it, is said to have left its site, not counted as a failure: your copies of its files may be the only ones left. It's asked about again once a week, and `library check` says when it's back. On a site that lists a mod's files side by side, without saying which replaced which, such as GameBanana's variants and add-ons, a newer main file is never another's update: a file has one once its author archives it, the newer file of its name, and the main files uploaded since the last check are new files, marked "(new file)", as optional ones are. It asks the site as little as it can: on Nexus Mods, once per game for the mods checked in the last 28 days, then only about mods whose files changed; GameBanana, which can't say what changed, about each watched mod. `library updates` lists every update found but a pinned mod's and the ones skipped, saying how many it leaves out; `--changelog` adds what changed in each. Downloading an update takes it off the list.
- `library move` moves the library's files to the same places under another folder, which becomes the library's root. It waits until downloads into the library are finished, never moves a file over another, and puts every file back if one can't move. Ctrl+C stops it; running the same command again finishes it. Your own files under the old root stay, and the folders it emptied are removed. Games with folders of their own (`games.<site>/<game>.root`) stay where they are, and the new root can't be one of their folders, inside one, or hold one.
- `library move-game` moves a game's files to the same places under a folder of its own, which becomes the game's folder (`games.<site>/<game>.root`); without a folder, it moves them back into the library's. The game is named as for `games.<site>/<game>`. It first says how many files move and how much room they take, from where to where, whether the folders are on one drive, and how much room the other drive has; only with `--yes` does it move them. A file already in the new folder at its size counts as moved, and its copy in the old folder stays for you to delete. It's refused for a folder that's the library's or another game's, inside one or holding one, while downloads of the game into its folder aren't finished, and when the files don't fit on another drive. Ctrl+C stops it and puts every file back.
- `library export` writes the library as a list of its mods and their files, by the sites' IDs, never by download links, which expire: each mod's site, game, ID, name, page, whether it's watched or pinned, its note, and its files but the old versions archived in `_archive`. Without `--to`, the list is written to the output; `--game` keeps to one game, named as for `games.<site>/<game>`. Nothing is asked of any site. The format, `modshelf-list` version 1, is JSON, described in [ADR 0098](adr/0098-mod-lists-and-collections.md).
- `library import` brings a list into the library, here or on another computer: a file `library export` wrote, or the link of a collection's page on its site, such as a Nexus Mods collection's (`https://www.nexusmods.com/games/<game>/collections/<slug>`, with `/revisions/<n>` for that revision, otherwise the latest). It first says what importing would do, from the library alone: how many mods are new to it, how many it has, how many are of sites ModShelf can't reach here, and how many files it would queue; for a collection, also the files its site no longer offers, and what it needs from elsewhere, such as a script extender, with each one's page, which ModShelf never downloads. Only with `--yes` does it import: the new mods are watched, with a list's pins and notes, and the listed files the library lacks are queued for it and downloaded, a collection's at the versions it pins. A mod the library has keeps its own watching, pin and note. `--watch-only` downloads nothing; `--optional` adds the files the list or collection marks optional; `--newest-for-missing` downloads a mod's newest main file in place of a listed one its site no longer offers. Files a free Nexus Mods account must start on the site wait, and the command lists their pages. It's refused while another process, such as the desktop app, runs the downloads: import there. Nothing is ever installed, and a collection's install steps aren't run. The exit code is 1 when anything couldn't be done, each named with why.
- `library import-archives` brings another mod manager's downloads of a game into the library, such as Mod Organizer 2's or Vortex's: the `.7z`, `.zip` and `.rar` files in the folder, not its subfolders. It reads each one once, and identifies it as a file of one of the game's mods, the cheapest way first: one the library has already, by its SHA-256, asks nothing; Mod Organizer 2's note beside it (`<archive>.meta`), or a name as Nexus Mods gives its archives (`Name-<mod>-<version>-<uploaded>.7z`), is checked against the mod's files on its site, by the file's ID or name and its size, one request a mod (two for a mod new to the library, read for its name); what's left is looked up by its content on its site, one request an archive, which Nexus Mods does by MD5 with a linked account. It first says about how many requests identifying takes, then each archive and what it is, or why it's left alone: in the library already, a copy of another in the folder, or unknown. Only with `--yes` does it import: each identified archive is copied where a download of it would go, its SHA-256 checked, its mod watched if it's new to the library, and the file recorded as found. The archives are only read: nothing in the folder is moved, changed or deleted, and nothing is installed. Ctrl+C stops it; run again, it goes on, as what it copied is in the library. A folder in the library is refused: rescan finds files there. The exit code is 1 when an archive couldn't be copied, each named with why.
- `library cleanup` lists what could go from the library's folders to free up space, as a table of each file's group, game, mod, path in its game's folder, size and state, then each group's total. The groups: `archived`, the old versions in `_archive` folders; `duplicates`, library files with the same SHA-256 and size as another, the copy kept being one outside an `_archive` folder, a watched mod's, then the one downloaded last; `unwatched`, the files of mods no longer watched; and `unmatched`, the files in the mods' folders that the library doesn't have and that match none of the mod's files on its site, as `library rescan` matches them. A file is in the first group that fits, in the order duplicates, archived, unwatched. An archived or unwatched file is kept when it may be the only copy left, its state saying why: its mod is gone from its site, or the site no longer offers it, or couldn't be asked; so is a file that matches nothing but turns out to be one of the mod's files on its site, which `library rescan` adds. Each mod's site is asked once at most, and only about mods with such files. `--game` keeps to one game, named as for `games.<site>/<game>`. `--delete` with a group says what deleting its files that can go would do; only with `--yes` does it delete them, one at a time, through the library, as deleting a file from its mod's page does, each recorded in the library's history. A file that changed since it was listed, or that can't be deleted, is left, with why, and the exit code is 1. Deleted files go for good, not to the trash; nothing else is ever deleted.


## Settings

- `settings show` lists the settings, marking the defaults, and says where they're kept. `settings set` changes one, and `settings reset` puts it back to its default. The settings and their values are listed in [settings.md](settings.md).

## Links from websites, diagnostics and the queue

- `links status` lists the sites whose websites hand downloads over with links of their own, Nexus Mods' `nxm://` links and Thunderstore's `ror2mm://` links, and which app opens them. `links take` makes the desktop app open them, remembering the app that did, such as r2modman for `ror2mm://`, and `links give-back` puts that app back; name the site, such as `links take thunderstore`. From a build from source, set `ModShelf__DesktopApp` to the desktop app's executable first; an installed ModShelf finds it beside the command line.
- `diagnostics` prints what a bug report needs: the version, the system, the folders (with how many games have folders of their own), the settings, counts of the library, the downloads and the accounts, and the deprecated arguments agents still use, such as `Legacy arguments: download.link ×3 (last 2026-11-03 22:31 UTC, claude-ai)`, with no keys, names or links.
- `queue list` shows every saved job without starting any download.

## Accounts

- `account list` shows the sources that support accounts, the account linked on each, and the ways to link one.
- `account link` asks for what the source needs. An API key isn't shown as you type it. For `browser`, it opens the site's sign-in page and waits until you approve ModShelf there; if no browser opens, it shows the page to open by hand. Linking again replaces the account.
- `account check` asks the site who the linked account is now, keeping a changed level, and shows what's left of the site's API requests: per day and per hour for Nexus Mods, with when each starts over.
- `account unlink` removes the account and deletes its stored credentials.
- **Nexus Mods:** `account link nexus` asks for your personal API key, from [your API keys page](https://next.nexusmods.com/settings/api-keys), and shows the account's name and level (Premium, Supporter or Free). Signing in through the browser is built, but Nexus Mods has to issue ModShelf a client ID first; to try it with one, set `ModShelf__Nexus__ClientId`, and `account link nexus --with browser` becomes available. Never commit a client ID.
- **GameBanana:** `account link gamebanana` asks for your member name, or your profile's link (`https://gamebanana.com/members/<number>`), and shows the profile's name. GameBanana gives apps no way to sign in, so nothing secret is asked, and ModShelf reads only what anyone can see on your profile: the mods you subscribe to, for `mod tracked` and Browse. A name no member has, or a profile GameBanana doesn't show, such as a private one, is refused. Everything else on GameBanana works without one.
- **mod.io:** `account link modio` asks for your API key or a personal access token, both made on [your API Access page](https://mod.io/me/access), and tells them apart by their shape. mod.io answers nothing without one, browsing included. An access token, with the `read` scope, shows your name and lists the mods you subscribe to; it lasts a year. An API key can't say whose it is, so the account is called "API key", and lists no subscriptions. ModShelf sends mod.io at most 60 requests a minute, and nothing for as long as mod.io asks after it says to slow down. It never subscribes to a mod: games install what's subscribed.

## Exit codes

- Exit codes: 0 done, 1 failed or refused, 2 bad input (arguments the command line can't read too), 3 still waiting to be started on the site, 70 something ModShelf didn't expect (said in a line, with the details in the log), 130 stopped with Ctrl+C.
