# ModShelf

ModShelf is a cross-platform desktop app for Windows, macOS and Linux that downloads mods from several mod sites and tracks their updates in one place. Nexus Mods is the first source; mod.io, Modrinth and CurseForge can follow as separate source projects.

ModShelf downloads and manages files. **It never installs mods**: it doesn't extract into game folders, deploy, manage load order, detect conflicts, run FOMOD installers or install collections.

> **Status:** Phase 5, the desktop app. The command line downloads files from Nexus Mods and from plain web links, keeps a library of the mods you download or watch, checks them for updates, and links a Nexus Mods account. The desktop app has its six screens in a sidebar, Library, Updates, Browse, Downloads, Accounts and Settings, and does the background work while it runs, in the tray with its window closed too: queued downloads, recording them into the library, and update checks with a notice of new updates. Every flow of the command line works from the app.

## Requirements

- [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0), version 10.0.100 or a later 10.0 feature band (pinned in `global.json`)
- An editor with .NET 10 support: Visual Studio 2026, Rider, or VS Code with the C# Dev Kit. Add the Avalonia extension for XAML previews. Visual Studio 2022 doesn't support .NET 10 projects.

## Build, test and run

Run these from the repository root, in PowerShell or any other shell:

```powershell
dotnet build                                 # must finish with 0 warnings, 0 errors
dotnet test                                  # runs every test project in ModShelf.slnx
dotnet run --project src/ModShelf.Desktop    # opens the desktop app
```

`dotnet test` runs on Microsoft.Testing.Platform, which `global.json` selects for the whole repository.

The tests never call a live mod site. Before a release, someone runs the manual checklists against Nexus Mods with a Premium and a free account: [docs/manual-checklist.md](docs/manual-checklist.md) for the command line, and [docs/manual-checklist-desktop.md](docs/manual-checklist-desktop.md) for the desktop app. [docs/manual-checklist-installer.md](docs/manual-checklist-installer.md) installs the app on each system and updates it from one version to the next.

To see a real notice on this computer, as the desktop app will show for new updates, run this one test with `MODSHELF_TEST_NOTICES` set to 1. It fails if the notice couldn't be shown, and says why.

```powershell
dotnet build
$env:MODSHELF_TEST_NOTICES = "1"
tests/ModShelf.Platform.Tests/bin/Debug/net10.0/ModShelf.Platform.Tests -method ModShelf.Platform.Tests.Notifications.NotificationServicesTests.ShowsARealNotice
```

### Installers

`build/pack.ps1` (PowerShell) and `build/pack.sh` (Bash) pack the desktop app's installers and update packages with [Velopack](https://velopack.io), whose `vpk` the scripts restore as a local tool, into `artifacts/releases`:

```powershell
./build/pack.ps1                                          # this system's, at the version MinVer gives
./build/pack.ps1 -Version 0.9.1 -Notes notes.md win-x64   # a version and its notes, for one runtime
```

Each runtime packs a self-contained publish: `win-x64` a per-user `Setup.exe` with a Start-menu shortcut, `linux-x64` an AppImage (which needs `mksquashfs`, and `zstd` for a delta package), and `osx-arm64` or `osx-x64` an app in a `.pkg`, on a Mac only. The installers aren't signed yet. Windows installs into `%LOCALAPPDATA%\ModShelf.App`, apart from `%LOCALAPPDATA%\ModShelf`, where the library stays when ModShelf is uninstalled. [ADR 0038](docs/adr/0038-installers-and-self-update.md) has the details. The command line, `ModShelf.Cli`, is in the same folder as the desktop app, so it updates with it: `%LOCALAPPDATA%\ModShelf.App\current\ModShelf.Cli.exe` on Windows, and `ModShelf.app/Contents/MacOS/ModShelf.Cli` on macOS. The AppImage holds it too, but starts only the desktop app ([ADR 0040](docs/adr/0040-the-mcp-server.md)). `build/render-icons.py` renders the Windows and macOS icons from `modshelf.svg`.

### Releasing

Releasing a version is tagging its commit, such as `v0.9.1`, and pushing the tag:

```powershell
git tag v0.9.1
git push origin v0.9.1
```

The release workflow, `.github/workflows/release.yml`, then tests the commit on the three systems, checks that the tag is the version MinVer gives it, writes the release notes from the `feat:` and `fix:` commits since the release before, packs `win-x64`, `linux-x64` and `osx-arm64`, and uploads them to one **draft** release, "ModShelf 0.9.1", a pre-release while ModShelf is 0.x. Installed apps see nothing until the draft is published: check its notes and files on the Releases page, then publish it. **Run workflow** on the Actions tab does all of it but the release, and keeps the packages with the run for 14 days, to download and try. [ADR 0039](docs/adr/0039-the-release-workflow.md) has the details; `build/release-notes.sh` shows the notes a tag would get.

### Desktop app

`dotnet run --project src/ModShelf.Desktop` opens the main window: a sidebar of the screens, Library, Updates, Browse, Downloads, Accounts and Settings, and the one selected. The button at the top of the sidebar hides the screens' names. **Search** under it, or Ctrl+K (⌘K on macOS) on any screen, opens quick search: with nothing typed, your last 10 searches that opened something and the screens; typing finds games, the one with most mods in the library first (opening in the Library when the library has its mods, in Browse otherwise), the library's mods (opening their page), the screens, and the settings that mention it (opening their category, or a game's own settings), names matched as the game picker matches them. ↑ and ↓ move, Enter opens, Escape closes. The window comes back as it was left: its size and place, maximized or not, the sidebar open or collapsed, and the screen last open; a window last on a screen that's gone, or larger than its screen now, comes back whole on a screen that's there. At the bottom of the sidebar, each linked account shows its picture, or its initial on a colour until the picture is saved or when the site has none, its name, and its level and site, such as "Premium · Nexus Mods"; with no account linked, **Link an account**. Each opens the Accounts screen; with the names hidden, the picture shows alone. While the app runs, queued downloads go on, finished ones go into the library, and the watched mods are checked for updates every `updates.interval`.

The first time the window closes, the app asks whether to keep running in the tray or quit, and remembers the answer (`window.closeToTray`, also on the Settings screen). In the tray, its icon opens the window, and its menu has **Open ModShelf**, **Check for updates now**, which says what it found in a notice, and **Quit ModShelf**; its tooltip counts the updates found. On Linux, the tray needs a tray host, which KDE and most desktops run and GNOME has with the AppIndicator extension; without one, closing the window quits. Starting the app again while it runs brings its window back instead of opening a second one; each library folder gets one app. It uses the same library database, settings, accounts and environment variables as the command line, so a library made with one shows in the other. One of them at a time runs the downloads: while a `download` command runs them, the Downloads screen says so, and the app starts its queue once the command has finished. When the library database can't be opened, the app says which file and why in a window, and closes. It logs to a file a day in a `logs` folder beside the database, such as `desktop-20261029.log`, keeping a week of them.

A new library, with no mods and no account linked, starts with a short setup over the main window: where the library goes, linking an account, and whether ModShelf opens Nexus Mods' `nxm://` links. Each step is the same as on the Settings or Accounts screen, where it can be changed later. **Finish** or **Skip setup** ends it for good; closing it otherwise shows it again at the next start.

Wherever you type to find a game or a mod by its name (the Library's filters, the game picker, Settings search, `mod games` and `mod_games`), each word you type must start a word of the name, in any order. Case, accents, apostrophes, quotes and other punctuation don't count, so a word may run on across the name's words: "stalker 2" finds S.T.A.L.K.E.R. 2: Heart of Chornobyl, "dragons dogma" Dragon's Dogma 2, "pokemon" Pokémon and "spiderman" Spider-Man. A Roman numeral from II to XXX is its number too: "final fantasy 12" finds Final Fantasy XII.

Once two sites are in use, those the library has mods of and those with an account linked, each game, mod, update and download from a mod site shows its site's name beside it, and the Library has a **Site** box beside the games' order, which shows one site's games and counts them alone; it starts on **All sites**. Direct links aren't a site. With Nexus Mods alone, nothing shows.

The Library screen shows the games of the mods you downloaded or watch, each with a cover, how many mods it has, the updates found for them, the room their files take on disk, archived versions included, and when they were last checked; a cover shows the game's banner from its site, saved like mods' pictures, and the game's initial on a colour of its own until the site answers, or when it gives none. A box filters the games by name, and they're ordered by most mods, the default, by name, by most room on disk, or with updates first. Games hidden in their settings are left out, with **Show hidden games** to show them too. Clicking a game shows its mods in a table: each mod's name and author, your version, what to know of it (an update, files missing from disk, or that it's watched only or not watched), its files, the room they take, and when its site last updated it. A box filters them by name or author; toggles show only the mods with an update, the watched ones, those with archived versions or those with files missing, each counting its mods, and with several on, the mods they all say; they're ordered by name, the default, with updates first, by when their site last updated them, by size, or by when they came into the library. Each mod has a box to select it, and **Select all shown** selects them all; **Update selected** downloads the selected mods' updates, and a mod a filter hides is no longer selected. **Library** at the top goes back to the games, and the gear beside a game's name opens its own settings. Clicking a mod's name opens its page in place of the list, as Browse shows it, with what the library has of it: its files, where they are, whether any is missing from disk, its archived versions when asked, each SHA-256 to copy, and in each file's **…** menu, **Delete…**, which deletes it from disk after asking; which of the site's files are updates for yours; and when it came into the library and was last checked. When the site can't be reached, the page shows the mod's saved details, says why, and offers **Try again**. Each mod's **…** menu also opens its page there or on its site, or its folder, watches or unwatches it, **Rescan** looks for its files placed by hand, and **Remove from library** takes the mod out of the library, leaving its files on disk. Each mod's **…** menu also has **Pin at this version**, which keeps its updates from being offered, counted or downloaded by **Update all**, its status saying "Pinned at 2.7" until **Unpin**; **Add a note…**, a note of several lines its page shows; and, once updates are skipped on the Updates screen, **Offer skipped updates again**. After **Remove from library**, **Unwatch**, **Pin at this version**, **Unpin**, a note emptied, or **Skip** on the Updates screen, a bar at the bottom of the screen says what happened, with **Undo**, for ten seconds, one change at a time; undoing puts the mod back as it was, with its updates, pin, skipped updates and note, and its files as the library has them now. Deleting a file isn't undone, and still asks first. **Rescan** at the top of the screen rescans every mod, and says what it found. **Recent activity** beside it shows what happened to the library's files over the last year, by day, the newest first: each file downloaded, with the version it replaced, each old version archived or deleted, each file a rescan found, and each mod removed, with its game; **Show** narrows it to one kind, and a mod's name opens its page, whose way back returns to the activity. It shows the newest 1,000. The games and mods show as Settings › General › **Previews** says: as rows with thumbnails, the default, as cards with large pictures, or as rows without them; in a narrow window, a table puts its numbers under the names. A game with previews of its own, from its settings, shows them on its page. The Updates screen lists the updates found for the watched mods by game, each heading with the game's icon from its site, but a pinned mod's and the ones skipped, a mod's new optional files among them, under a line that counts them and says when the mods were checked and when the next check is, with **Check now**. Each update says its change of version, such as "1.3 → 1.4", and shows its version's entry in the mod's changelog, read the first time you open the screen, a few mods at a time, and kept while the app runs. **Download** puts an update into the library beside the file it replaces, and **Skip** leaves it out until a newer one comes; **Update all**, at the top or on a game's heading, downloads them all, or the game's, one after the other, and a game's mods in the Library have it on their heading too. With a free Nexus Mods account, each file then waits for you on the Downloads screen. Both screens follow the library as it changes, and the badge on Updates counts the updates; a hidden game's are left out of both.

Mods' pictures come from their sites, and their details, such as which picture is theirs, are saved in the library database, so the screens show them at once and offline; saved details are read from the site again once they're a day old (`details.maxAge`). The pictures are saved in a `pictures` folder beside the database, up to 512 MB (`pictures.maxSize`); the ones shown least recently go first. An adult mod's picture is blurred, with the site's blurred thumbnail when it has one, unless `pictures.adult` says `hidden` or `shown`. Nexus Mods gives its mods' thumbnails and blurred thumbnails through its GraphQL API, which ModShelf asks first for a mod's details; a mod it doesn't give is read from the older API, without thumbnails, so its thumbnail is its full picture, made small.

The Browse screen searches a game's mods on Nexus Mods, which needs a linked account. Pick the game in the game picker, which leaves out hidden games. Under its field, **Your games** are the library's, the one with the most mods first, each saying how many; typing finds the site's other games too, those whose names start with it first, 50 at most; with nothing typed, it offers Browse's last 10 searches, which search again in the chosen game, and are kept in `ui-state.json` between runs. ↑ and ↓ move from game to game, Enter chooses, and Escape closes the list; the game chosen shows as a chip in the field, its site beside it when the games come from two sites, and its × lets you choose another. Choosing a game starts the order, the time and the page size as the game's own settings say, when it has some: until you search, the game's page shows three rows of mods, **Trending** (from the site's own list), **Recently added** and **Recently updated**, each with **Show all** for every mod in that order but Trending; clearing the words searched for brings the rows back. Search by words; **Filters** opens a card over the results with the order, one of fourteen (by relevance, endorsements, downloads, unique downloads, last update, publishing, size or name), the mods updated in the last 24 hours, week or month, one of the game's categories, an author, adult content, and 20, 50 or 100 a page. What's changed there searches once you **Apply**; **Close** or Escape leaves what was applied, and **Reset** puts the card back to how the game starts. Each filter applied but the order and page size shows as a chip under the search, such as "Category: Armour", whose × removes it at once, with **Clear all**; the button counts them ("Filters · 2"), and the results say their order. **Load more** lists the next page. The card offers only what the game's site can search by, in its own words, such as Nexus Mods' endorsements; a game's saved order or page size its site lacks starts on the site's own. Each game keeps its filters while the app runs: choosing it again brings them back. Sorted by size, each mod says its size; by newest, when it was added; by last update, when. A link to a mod in the search box opens that mod. Each mod has a box to select it, and **Select all shown** selects every mod listed; **Download selected** puts the newest main file of each into the library, and says how many it queued, which were in the library already, and what couldn't be queued. A new search starts with none selected. The view switch beside **Filters** shows the results as cards with each mod's picture, the default, as rows with thumbnails, or as rows without pictures; a chosen game with previews of its own shows those, and the switch changes the game's. Clicking a mod opens its page: its picture, as the previews say, its details and category, its files by section, with **Download** into the library and **Save to a folder…** for each, its changelog's latest entries, newest first, with the rest when asked, and what it needs, where the site says (a mod it needs opens on its page in ModShelf, anything else in the browser). It can be watched in the library, and tracked on Nexus Mods; one in the library can be rescanned or removed there. **Tracked mods** lists the mods of the game you track there.

The Downloads screen takes a link to a mod or a file: **Download** puts it into the library, and **Save to a folder…** into a folder you pick. A line under the heading says what's under way, how fast, and what waits for you. It lists every download, newest first, with its progress, speed and time left, and the buttons to pause, resume, retry or cancel it; the tabs above the list show all of them, or those under way, waiting for you, failed or finished, each with its count. Cancelling a download with bytes saved asks first. **Clear finished** removes the done and cancelled downloads from the list; their files stay. A download Nexus Mods wants started on its website shows **Open on Nexus Mods** and **Paste link…**: start it there with the download for mod managers, copy the `nxm://` link its button holds, and paste it; or, once ModShelf opens `nxm://` links (Settings), the download goes on by itself. While files wait for you, a strip above the list counts them, and **Open the next page** opens the page of the one that has waited longest, one page a click. The badge on Downloads counts the downloads waiting for you, to be started or because they failed. Updates and Downloads show their mods' thumbnails when Settings › General › **Previews** says **Thumbnails**; by default, they show rows without them.

The Accounts screen has a card for each site that can link an account: the account's picture, name, level and the day it was linked, and what's left of the site's API requests, as it last said. While fewer than 10% of a site's requests for the hour or the day are left (`quota.warnBelow`, in Settings › Updates), a calm strip at the top of the window says how many and when they renew, warm once they're used up; its × hides it until they renew. Before **Check now**, **Update all**, **Update selected** or **Download selected**, when the work would likely take more requests than the site has left, the app says so and asks whether to go on: a check takes one request for each game and one for each mod never checked or due a full check, and a download two. A button for each way the site offers links an account: an API key pasted into a box that hides it, with a button that opens the site's API keys page; a code the site emails; or approving ModShelf in the browser, with **Open page again** and **Cancel** while it waits. **Check** asks the site who the account is now, which also brings the API requests left up to date; ModShelf asks the site nothing on this screen otherwise. **Unlink** removes the account and its stored credentials, after asking. Each time the screen is shown, it lists the accounts again, such as one linked from the command line meanwhile.

The installed app updates itself from ModShelf's GitHub releases, pre-releases included while it's 0.x. As it starts, it looks for a newer release, and when there is one, the Settings screen's badge and its "About ModShelf" card say so, with what's new. **Download** downloads it, and **Restart to update** quits and starts the new release in its place; nothing changes until then, however often ModShelf starts. **Check for updates** looks again, and "Look for a newer ModShelf when it starts" (`app.checkForUpdates`) turns the look at start off. A build from source doesn't update itself. To try updates against releases of your own, set `ModShelf__UpdateFeed` to a folder `build/pack.ps1` packed into. On Windows, a click on one of ModShelf's notices opens the Updates screen, and uninstalling gives the `nxm://` links back to the app that had them. On Linux and macOS, give them back on the Settings screen before deleting the app.

The Settings screen changes what `settings set` does, in categories: **General** (the theme, closing the window, previews, pictures and mod details), **Library** (its folder, the folder pattern, old versions and **Rescan the library**), **Updates**, **Links**, **Games** (each game's own settings) and **About**. **Search settings** shows the settings that say every word typed, from every category, and **Games** with the games whose names match; choosing a category, or Escape, ends the search. **Choose another folder…** moves the library, with its files after asking, and **Use the default folder** moves it back; games with folders of their own stay where they are. The folder pattern shows where a sample file would go as you type, and is saved with **Save**. **Previews** says how each screen shows its mods, the Library, Browse, Updates and Downloads: as **Rows**, **Thumbnails** or, in the Library and Browse, **Cards**; Browse's view switch changes Browse's too. **Games** lists the library's games and those with settings of their own, and **Add a game…** finds another by its name among the sites' games not listed yet, or adds one by the key its site names it by, such as `stardewvalley`, when the sites can't list theirs. A game's page says where its files are, how many and how much room they take: in the library's folder, or a folder of their own. **Choose…** picks another, then says what would move, from where to where, the room there, the files there already and any missing from disk, and **Move** moves them, with how far it is; **Stop** puts back every file moved. A drive without room enough, or a folder the files can't go to, such as one inside another game's, is refused, with **Choose another folder…**, and a move that stopped says why, with **Try again**. **Move back to the library** moves them back, and a game without files takes the folder at once. The page shows each of its other settings using every game's, which it says, until **Override** gives the game its own, which **Use default** gives back: its folder pattern, old versions, update checks (whether its mods are checked with the other games, and how often), notices, previews (how its mods show on its Library page and in Browse), and how Browse starts for it; and **Hide** leaves it out of the Library, Updates and Browse, its mods still checked. What happens to old versions, how often to check for updates, whether to show a notice, and whether the app is light or dark are saved as you choose them; the theme changes at once. "Pictures and mod details" shows how much room the saved pictures take, with **Clear**, and sets the most they may take, how long mod details are kept, and whether adult mods' pictures are hidden, blurred or shown. **Links from websites** says which app opens Nexus Mods' `nxm://` links, the ones its **Mod manager download** buttons hand over: **Open them with ModShelf** makes it ModShelf, remembering the app that had them, such as Vortex or Mod Organizer 2, and **Give them back** puts that app back. While ModShelf opens them, a click on the website brings the app forward on the Downloads screen: a download waiting for that file goes on, and otherwise the file goes into the library, whether the app was running or not. On macOS, only the installed app can open them. The screen also says where the settings are kept, and warns when no keyring protects the credentials. Each time it's shown, it shows the settings as stored, such as previews changed in Browse or a change from the command line.

### Command line

The headless host in `src/ModShelf.Cli` builds the same dependency-injection container as the desktop app and drives the engine directly:

```powershell
dotnet run --project src/ModShelf.Cli -- download <link> [--to <folder> [--name <file>]]
dotnet run --project src/ModShelf.Cli -- mod show <link> [--all] [--changelog]
dotnet run --project src/ModShelf.Cli -- mod games [words] [--source <site>] [--page <n>] [--page-size <count>]
dotnet run --project src/ModShelf.Cli -- mod search [words] --game <game> [--author <name>] [--category <name>] [--updated-within <days>] [--adult] [--sort <order>] [--ascending] [--page <n>] [--page-size <count>]
dotnet run --project src/ModShelf.Cli -- mod updates --game <game> [--since 1d|7d|28d|<date>]
dotnet run --project src/ModShelf.Cli -- mod tracked
dotnet run --project src/ModShelf.Cli -- mod track <link>
dotnet run --project src/ModShelf.Cli -- mod untrack <link>
dotnet run --project src/ModShelf.Cli -- library list [--files]
dotnet run --project src/ModShelf.Cli -- library watch <link>
dotnet run --project src/ModShelf.Cli -- library unwatch <link>
dotnet run --project src/ModShelf.Cli -- library pin <link>
dotnet run --project src/ModShelf.Cli -- library unpin <link>
dotnet run --project src/ModShelf.Cli -- library skip <update link> [--undo]
dotnet run --project src/ModShelf.Cli -- library note <link> [text] [--clear]
dotnet run --project src/ModShelf.Cli -- library forget <link>
dotnet run --project src/ModShelf.Cli -- library rescan [link]
dotnet run --project src/ModShelf.Cli -- library check
dotnet run --project src/ModShelf.Cli -- library updates [--changelog]
dotnet run --project src/ModShelf.Cli -- library move <folder>
dotnet run --project src/ModShelf.Cli -- library move-game <game> [folder] [--yes]
dotnet run --project src/ModShelf.Cli -- settings show
dotnet run --project src/ModShelf.Cli -- settings set <setting> <value>
dotnet run --project src/ModShelf.Cli -- settings reset <setting>
dotnet run --project src/ModShelf.Cli -- links status|take|give-back [site]
dotnet run --project src/ModShelf.Cli -- diagnostics
dotnet run --project src/ModShelf.Cli -- queue list
dotnet run --project src/ModShelf.Cli -- account list
dotnet run --project src/ModShelf.Cli -- account link <source> [--with api-key|browser|email]
dotnet run --project src/ModShelf.Cli -- account check <source>
dotnet run --project src/ModShelf.Cli -- account unlink <source>
dotnet run --project src/ModShelf.Cli -- mcp
```

- `download` queues the file and shows its progress until it's done. Put the link in quotes, since shells treat characters such as `&` specially. A file that won't fit on the disk fails before anything is written. One process at a time runs the downloads of a library: while the desktop app or another `download` runs them, `download` says so and exits 1, leaving the queue alone.
- **Into the library:** without `--to`, the file goes under the library root, or its game's own folder when it has one (`games.<site>/<game>.root`), in its mod's folder, and the library records it, with its mod watched for updates. The file keeps the name its site gives it, made safe on every system; when another file has that name, the file's ID is added to it. A file the library has, still on disk, isn't downloaded again. Only files of mods on sites such as Nexus Mods go into the library.
- **Old versions:** the files a download replaced, as its site says (Nexus Mods' update chains), are its old versions. By default, the two newest versions stay and older ones are **deleted for good**, once the library has recorded the new file; `library.oldVersions` can keep them all, or move them to an `_archive` folder instead. `download` says what it moved or deleted.
- **Into a folder of your own:** `--to` saves any file there, such as one from a plain web link, and `--name` picks its name. The folder is created if it doesn't exist; a file there instead is refused. A file saved there already by an earlier `download` isn't downloaded again. To check the file against a hash, end the link with `#sha256=<hex>` (or `md5`, `sha1`, `sha512`); the fragment is never sent to the server.
- Ctrl+C stops the download and keeps what's downloaded so far. Running the same command again continues where it stopped, including after a crash.
- When a site wants a download started on its website, `download` opens the page in your browser, shows it, and asks for the link the site then hands over. Paste it and press Enter, and the download carries on. Ctrl+C leaves the download waiting; running the same command again shows the page again.
- **Nexus Mods downloads:** `download` takes a mod's page (its newest main file), a file's link from the mod's Files tab, or an `nxm://` link, and needs a linked account. Premium accounts download straight away. Free accounts start each download on the website with "Slow download"; the website then hands your browser an `nxm://` link to paste. While the desktop app opens these links (`links take`), it gets the link instead and carries the download on there. Otherwise the app that opens them gets it, such as Vortex or Mod Organizer 2; with none, the browser usually shows the link it couldn't open: Chrome and Edge in the developer tools' console, Firefox in its address bar. `download "nxm://…"` on its own also finishes a download waiting for it: in the library, or with `--to`, in that folder.
- `mod show` looks a mod up from a link to it or to one of its files, and prints its details and its files by section, newest first, each with the link to download it. The file the link points to is marked. `--all` adds old versions, archived files and files in no section; `--changelog` adds the changelog. Nothing is downloaded.
- `mod games` lists a site's games whose names match the words, those that start with them first, each with the key `mod search --game` takes, 20 a page unless `--page-size` says (1 to 100); `--page` picks the page, and `--source` the site, when more than one has games.
- `mod search` lists a game's mods whose names hold the words, a page at a time, with author, approval in the site's words (endorsements on Nexus Mods; no column for a site without), downloads, last update and the link `mod show` and `download` take. The game is named as in the site's links, such as `stardewvalley` for Nexus Mods. `--author` keeps one author's mods, `--category` one of the game's categories, by its name in any case (one the game doesn't have is refused, naming those it has), `--updated-within` the mods updated within that many days, counted from the start of the hour, and `--adult` includes mods with adult content. `--sort` orders by `Relevance`, `Endorsements` (whatever the site counts as approval), `Downloads`, `UniqueDownloads`, `Updated`, `Newest`, `Size` or `Name`, the most first, and by name from Z; the site's own order unless set (relevance on Nexus Mods, which without words is its own order). `--ascending` puts the least first, such as the oldest, or names from A. `--page` picks the page, and `--page-size` how many mods it lists, from 1 to 100 and as many as the site's pages hold (20 unless set, or fewer when the site's pages hold fewer). A search the site can't do, such as by author on a site that can't, is refused, saying what it can.
- `mod updates` lists a game's mods that changed since a time, in one request: each with when its files last changed, when it was last active, and its link. Mods with new or changed files since then are marked; the others only changed their pages, such as their descriptions or comments. `--since` takes `1d` (the default), `7d` or `28d`, or a date or time such as `2026-10-20` or `2026-10-20T18:00`, in local time unless it gives an offset. Nexus Mods lists the last 28 days only.
- `mod tracked` lists the mods your linked account follows on the site. `mod track` and `mod untrack` follow the mod a link is to, or stop following it, as the site's button does; doing either twice changes nothing. They say it in the site's words, such as "Tracked on Nexus Mods: mod 12604 of skyrimspecialedition." and "12 tracked mods on Nexus Mods."
- When more than one site can search, list updates or follow mods, `--source` picks one, such as `--source nexus`. Messages name a site by its name, such as "mod 12604 of skyrimspecialedition on Nexus Mods", and by its ID where you type it, such as `account link nexus`.
- `library list` shows the library: the mods ModShelf watches for updates, and the ones with downloaded files, each with its link; `--files` also lists each file with its version, size, SHA-256 and path. The SHA-256 is read once, when a download is recorded; a file recorded before 0.9.2 has none until a rescan reads it. `library watch` adds the mod a link is to and watches it; `library unwatch` stops watching it, and a mod without downloaded files leaves the library. `library forget` takes a mod out of the library, with its updates, so it isn't watched any more: its downloaded files stay on disk, no longer the library's, so moving the library leaves them behind, and its completed downloads leave the downloads list, which would add them back. It waits until the mod's downloads into the library are finished. Watching is ModShelf's own, apart from a site's tracked mods.
- `library pin` pins a library mod at the version it has: its updates are still found, but aren't offered, so `library updates`, `library check`, the desktop app and its notices leave them out; `library unpin` offers them again. `library skip` skips one update, by the link `library updates` gives it, until a newer one comes, and `--undo` offers it again. `library note` keeps a note of a mod, up to 2,000 characters, in place of the one it had, and `--clear` removes it. None of them asks the site, and `library list` says which mods are pinned, and lists the notes.
- `library rescan` looks in the mods' folders, where their files are and where the folder pattern puts new ones, each with its `_archive` folder, for files the library doesn't know, such as ones downloaded outside ModShelf. It adds each that matches one of the mod's files on its site by name, as ModShelf saves it or with the file's ID added, and by size, within 1 KB, and reads the SHA-256 of the library's files that have none. It says which files are missing from disk, and which in the folders match nothing. With a link, it rescans that mod, which comes into the library, watched, when its files are found where the folder pattern puts them, as a forgotten mod's do. Nothing is moved, renamed or deleted, and the site is asked only about mods with files to match.
- `library check` checks the watched mods for updates now, and lists the new ones with the link to download each. An update is the newest file of a downloaded file's update chain on the site, or, for a main file the author didn't link, a newer main file; for a mod that's only watched, a main file uploaded since the last check. A mod with files also gets the optional files uploaded since the last check that it doesn't have, marked as new optional files; once one is downloaded, its own updates follow. Version labels are never compared. It asks the site as little as it can: once per game for the mods checked in the last 28 days, then only about mods whose files changed. `library updates` lists every update found but a pinned mod's and the ones skipped, saying how many it leaves out; `--changelog` adds what changed in each. Downloading an update takes it off the list.
- `library move` moves the library's files to the same places under another folder, which becomes the library's root. It waits until downloads into the library are finished, never moves a file over another, and puts every file back if one can't move. Ctrl+C stops it; running the same command again finishes it. Your own files under the old root stay, and the folders it emptied are removed. Games with folders of their own (`games.<site>/<game>.root`) stay where they are, and the new root can't be one of their folders, inside one, or hold one.
- `library move-game` moves a game's files to the same places under a folder of its own, which becomes the game's folder (`games.<site>/<game>.root`); without a folder, it moves them back into the library's. The game is named as for `games.<site>/<game>`. It first says how many files move and how much room they take, from where to where, whether the folders are on one drive, and how much room the other drive has; only with `--yes` does it move them. A file already in the new folder at its size counts as moved, and its copy in the old folder stays for you to delete. It's refused for a folder that's the library's or another game's, inside one or holding one, while downloads of the game into its folder aren't finished, and when the files don't fit on another drive. Ctrl+C stops it and puts every file back.
- `settings show` lists the settings, marking the defaults, and says where they're kept. `settings set` changes one, and `settings reset` puts it back to its default:
  - `library.root` is the library's folder: a ModShelf folder in your Downloads folder unless set. Once the library has files, `library move` changes it instead, taking them along.
  - `library.folders` is where files go under it, as folders separated by `/` and ending in `{file}`. The folders mix text with `{source}`, `{game}`, `{mod}` and `{modid}`, such as the default, `{source}/{game}/{mod} ({modid})/{file}`. A mod keeps its folder when its site renames it.
  - `library.folders.<site>/<game>` is a pattern for one game, named by its site and as in the site's links, such as `library.folders.nexus/skyrimspecialedition`. The game's key alone, as `library.folders.skyrimspecialedition`, does while only one site's game in the library or the settings has it, or only one site has games; `settings show` gives the full name.
  - `library.oldVersions` is what happens to a file's old versions when a newer one is downloaded: `all` keeps them, `archive` moves them to an `_archive` folder in their folder, and a number keeps that many versions, the newest first, and deletes the others. The default is `2`.
  - `updates.interval` is how often the desktop app will check the watched mods for updates: minutes, hours or days, such as `30m`, `6h` or `1d`, from 15 minutes to 7 days. The default is `6h`. The command line checks only when asked.
  - `updates.notify` is whether a background check that finds new updates shows a notice: `true`, the default, or `false`. Windows shows it as a toast from ModShelf, macOS through Script Editor for now, and Linux through libnotify, which most desktops have. The command line only prints what `library check` finds.
  - `appearance.theme` is whether the desktop app is `light` or `dark`, or follows the system's mode: `system`, the default.
  - `window.closeToTray` is whether closing the desktop app's window keeps it running in the tray (`true`) or quits it (`false`). Until it's set, the app asks the first time.
  - `setup.done` is whether the desktop app's first-run setup was finished or skipped. `settings reset setup.done` shows it again at the next start of a library with no mods and no account linked.
  - `app.checkForUpdates` is whether the installed desktop app looks for a newer ModShelf when it starts: `true`, the default, or `false`, when it looks only when asked, on its Settings screen.
  - `previews.library`, `previews.browse`, `previews.updates` and `previews.downloads` are how the desktop app's screens show their mods: `off`, `thumbnails` or `cards`. The defaults are `thumbnails` for Library, `cards` for Browse, and `off` for the others, which show cards as thumbnails.
  - `pictures.maxSize` is the most room, in megabytes, mods' saved pictures take, from 64 to 8192: `512` unless set. The ones shown least recently go first.
  - `pictures.adult` is how the desktop app shows the pictures of mods with adult content: `hidden`, `blurred`, the default, or `shown`.
  - `details.maxAge` is how old mods' saved details get before they're read from their site again: minutes, hours or days, such as `6h` or `7d`, from 15 minutes to 7 days. The default is `1d`.
  - `quota.warnBelow` is below what share of a site's requests for the hour or the day the desktop app warns that they run low: a percent from 0, for never, to 90. The default is `10`.
  - `games.<site>/<game>.<setting>` is one game's own setting, in place of every game's, with the game named as for `library.folders.<site>/<game>`, such as `games.nexus/stardewvalley.notify`. The same game on two sites is two games, each with settings of its own. `settings reset` sets it back to every game's. `games.<site>/<game>.folders` is the same as `library.folders.<site>/<game>`, which `settings show` lists. Before 1.0.0, `settings.json` named a game by its key alone; such a game is Nexus Mods', and is named by its site from the next change on. `oldVersions`, `updateInterval` and `notify` take the values `library.oldVersions`, `updates.interval` and `updates.notify` take. `checkUpdates` set to `false` leaves the game out of the background checks, `library check` and the desktop app's Check now; only checking the game alone checks it. `hidden` set to `true` leaves the game out of the desktop app's lists, though its mods are still checked. `root` is a folder of the game's own, a full path, where its files go in place of `library.root`, the folder pattern still saying where below it; it changes this way only while the game has no files, and `library move-game`, or the desktop app's Settings › Games, moves a game with files. Copying another game's settings leaves it as it is. `browse.sort` (an order, as `mod search --sort` takes it, in lower case), `browse.direction` (`ascending` or `descending`), `browse.window` (`1d`, `7d` or `30d`) and `browse.pageSize` (`20`, `50` or `100`) are how the desktop app's Browse screen starts for the game; what the game's site can't search by is refused. `previews` (`off`, `thumbnails` or `cards`) is how the game's mods show on its page in the Library and in Browse while it's chosen, in place of `previews.library` and `previews.browse`.
- `links status` lists the sites whose websites hand downloads over with links of their own, such as Nexus Mods' `nxm://` links, and which app opens them. `links take` makes the desktop app open them, remembering the app that did, and `links give-back` puts that app back; the site can be left out while Nexus Mods is the only one. From a build from source, set `ModShelf__DesktopApp` to the desktop app's executable first; an installed ModShelf finds it beside the command line.
- `diagnostics` prints what a bug report needs: the version, the system, the folders (with how many games have folders of their own), the settings, counts of the library, the downloads and the accounts, and the deprecated arguments agents still use, such as `Legacy arguments: download.link ×3 (last 2026-11-03 22:31 UTC, claude-ai)`, with no keys, names or links.
- `queue list` shows every saved job without starting any download.
- `account list` shows the sources that support accounts, the account linked on each, and the ways to link one.
- `account link` asks for what the source needs. An API key isn't shown as you type it. For `browser`, it opens the site's sign-in page and waits until you approve ModShelf there; if no browser opens, it shows the page to open by hand. Linking again replaces the account.
- `account check` asks the site who the linked account is now, keeping a changed level, and shows what's left of the site's API requests: per day and per hour for Nexus Mods, with when each starts over.
- `account unlink` removes the account and deletes its stored credentials.
- **Nexus Mods:** `account link nexus` asks for your personal API key, from [your API keys page](https://next.nexusmods.com/settings/api-keys), and shows the account's name and level (Premium, Supporter or Free). Signing in through the browser is built, but Nexus Mods has to issue ModShelf a client ID first; to try it with one, set `ModShelf__Nexus__ClientId`, and `account link nexus --with browser` becomes available. Never commit a client ID.
- Exit codes: 0 done, 1 failed or refused, 2 bad input (arguments the command line can't read too), 3 still waiting to be started on the site, 70 something ModShelf didn't expect (said in a line, with the details in the log), 130 stopped with Ctrl+C.
- Jobs, the library and linked accounts live in the library database, `library.db` under the user's local application data folder (`%LOCALAPPDATA%\ModShelf` on Windows), and the settings in `settings.json` beside it, with the count of deprecated MCP calls in `deprecated-calls.json`, and what the desktop app remembers for you, the window's place, the sidebar, the screen last open, and the recent searches of Browse and of quick search, in `ui-state.json`. To use another database, for example while testing, set the environment variable `ModShelf__DatabasePath`; the settings and the count move with it.
- Credentials never go in the database. They go to the system's secret store: DPAPI-encrypted files on Windows, the Keychain on macOS, and the Secret Service keyring on Linux. Without a keyring (libsecret missing, no session bus, or no Secret Service on it), Linux falls back to files encrypted for this computer, and the account commands warn about it. A keyring that's there but fails, such as one that's locked or doesn't answer, is still used: ModShelf logs that it failed, and linking or unlinking says why it couldn't. To keep test credentials apart from your own, set `ModShelf__SecretScope` to another name (the Keychain and the keyring) and `ModShelf__SecretsFolder` to another folder (the files).
- Logs go to stderr, warnings only (`Logging__LogLevel__Default=Debug` shows more there), and to a log file a day in a `logs` folder beside the library database, such as `cli-20261029.log`, from Information up. A week of files is kept.
- A library database that can't be opened, such as a damaged one or one another program holds, is named, with what's wrong and what to do; ModShelf leaves it as it is, and every command exits 1.
- `mcp` runs ModShelf's MCP server, for an AI agent: see below.

### MCP server

`mcp` runs an [MCP](https://modelcontextprotocol.io) server on standard input and output, which an agent's app, such as Claude Desktop or Claude Code, starts and talks to. Through it, an agent can see the library, its updates, the downloads and the settings, and act on them, such as when it helps you keep a mod manager's mods up to date: ModShelf downloads the files and keeps their versions, and the mod manager installs them. ModShelf never installs mods. Its tools:

- `library_list`, the mods and their files, with absolute paths, versions, sizes and SHA-256s, whether they're archived old versions, and whether they're missing from disk, a page at a time (50 mods unless `limit` says otherwise), for a game, a site or a mod if asked, watched ones, ones with updates or ones with files missing from disk only (`watchedOnly`, `updatesOnly`, `missingOnly`), or `compact`, with counts in place of files; `library_changes`, the files downloaded since a time, each with the older version it replaced and what became of it (`archived`, `deleted`, `kept`, or `gone` from the library otherwise), and its mod's other files in the library; `library_updates`, the updates found, each with its link, the library file it replaces, and its `kind`, `update` or `newFile` for a file that replaces none, such as a new optional file, and with `changelog`, what changed; `library_check`, which checks the watched mods now; `library_watch` and `library_unwatch`; `library_forget`, which takes a mod out of the library as `library forget` does, its files staying on disk; `library_rescan`, as `library rescan` does; and `library_pin`, `library_skip` and `library_note`, as `library pin`, `library skip` and `library note` do. `library_updates` and `library_check` leave out a pinned mod's updates and the ones skipped, which `library_list` and `mod_show` still give, each saying whether it's skipped, with each mod's `pinned` and `note`.
- `download`, which downloads files' or mods' links into the library, as the desktop app does: from 1 to 50 links in `links`, in the order given (`link`, one link as `download` took before 0.9.3, still works until ModShelf 2.0 but is deprecated; see below), each with its own result, so one that can't be downloaded says why and the others go on, and each download as it is when the call ends, such as downloaded already or failed; `downloads_list`; and `downloads_pause`, `downloads_resume`, `downloads_retry` and `downloads_cancel`, by a download's ID or its first 8 characters.
- `mod_games`, as `mod games` does, a page at a time; `mod_show` and `mod_search`, as `mod show` and `mod search` do, `mod_search` with `category` and `updatedWithin` too, and with what the site's search can do for the game in each result's `search`: its orders and which ways round, the filters it takes, its largest page, its word for approval, and the game's categories; `mod_show` with where the library has each file, the newer file that replaces it (Nexus Mods lists some links back in time, to a file uploaded before, which are left out), and, in `libraryOnly`, the library's files the site no longer lists, such as a pulled file; `settings_show`, `settings_set` and `settings_reset`, as `settings` does; `accounts_status`, whether an account is linked on each site, and its level, never whose it is or its key; and `diagnostics`.

An argument renamed in a release still works until the next major version. A call that uses it gets a `deprecated` block in its result (a code such as `DL_LINK_ARG`, the old argument, the one to use, the version that removes it, and an example with the call's own values), a note at the start of its message, a warning in the log, and a count in `deprecated-calls.json` beside `settings.json`, which `diagnostics` reports. Its description starts with "Deprecated", and its input schema marks it `deprecated`. A call whose arguments don't fit the tool, such as from an agent's app whose list of the tools is older than the server, fails saying what the tool takes; restarting the agent's app and starting a new conversation reads the tools again. It can't link accounts, delete the library's files, move the library, or take a site's links: those stay yours, in the desktop app or the command line. While the desktop app runs, the server asks it to download and change the downloads; otherwise it runs the downloads itself until none is under way, and closing it pauses what's left, which goes on the next time ModShelf runs the downloads. With a free Nexus Mods account, each download waits for you to start it on the website: `download` gives the page, and the desktop app, which the website's link starts, carries it on. The library keeps a year of what happened to its files, from 0.9.3 on: a file downloaded before then, or found by a rescan, says nothing of what it replaced, and `library_changes` reads the newest 1,000 events. The server logs to `cli-….log` with the command line, and never logs links. On Windows, **Restart to update** also ends a server started from the installed app; restart the agent's app to start it again.

For Claude Desktop, add it to `claude_desktop_config.json` (**Settings**, **Developer**, **Edit Config**), with your own user folder, then restart Claude Desktop:

```json
{
  "mcpServers": {
    "modshelf": {
      "command": "C:\\Users\\<you>\\AppData\\Local\\ModShelf.App\\current\\ModShelf.Cli.exe",
      "args": ["mcp"]
    }
  }
}
```

For Claude Code, in PowerShell: `claude mcp add --transport stdio modshelf -- "$env:LOCALAPPDATA\ModShelf.App\current\ModShelf.Cli.exe" mcp`. On macOS, the command is `/Applications/ModShelf.app/Contents/MacOS/ModShelf.Cli`. From a build, it's the `ModShelf.Cli` executable in `src/ModShelf.Cli/bin/Debug/net10.0`, not `dotnet run`, which can write the build's output where the protocol goes. The environment variables the command line takes, such as `ModShelf__DatabasePath`, go in the app's configuration of the server (`"env"` in Claude Desktop's). [ADR 0040](docs/adr/0040-the-mcp-server.md) has the details, and [docs/manual-checklist-mcp.md](docs/manual-checklist-mcp.md) the checks to make by hand.

## Solution layout

```
build/                            packing the installers (pack.ps1, pack.sh), the release notes, the macOS Info.plist, and the icons
src/
  ModShelf.Domain                 entities and value objects, no dependencies
  ModShelf.Sources.Abstractions   IModSource and the capability interfaces a source implements
  ModShelf.Application            use cases and ports
  ModShelf.Infrastructure         storage, HTTP file transfer, settings, logging
  ModShelf.Platform               OS integration (secret stores, nxm:// handler, notifications)
  ModShelf.Sources.Nexus          the Nexus Mods source
  ModShelf.Sources.DirectUrl      plain web links, with no mod site involved
  ModShelf.Presentation           ViewModels, no Avalonia reference
  ModShelf.Desktop                Avalonia views and the desktop composition root
  ModShelf.Cli                    headless composition root: the commands, and the MCP server
tests/
  ModShelf.<Library>.Tests        one test project per library
  ModShelf.Architecture.Tests     enforces the dependency rules, keeps the installer out of ModShelf's data folder, and checks the release notes
  ModShelf.Cli.Tests              runs the CLI end to end: stop, kill and resume a download; finish one through a handoff; download into the library, move it and check it for updates; look up and search mods; link, check, refresh and unlink fake accounts; and the MCP server's tools, with a client
  Shared                          code several test projects compile in: SourceContractTests, TempFolder, the log recorders
```

Dependencies point inward toward Domain, and each mod site lives in its own source project that sees only `Sources.Abstractions`. The architecture tests fail, locally and in CI, if a project gains a reference it isn't allowed to have. See [ADR 0001](docs/adr/0001-layered-architecture.md) for the rules and the reasoning behind them. Where files, types and members go inside each project is in [docs/code-organization.md](docs/code-organization.md).
